首个 token 一致，为什么还要查下一步

首个 token 由当前 logits 的最高分决定，后续 token 的计算还要读取 Prefill 留下的状态。已有三端矩阵中，第 2 层卷积状态的 310P–CPro 余弦已降至 0.250325，同一对平台的 logits 余弦仍为 0.989347。

连续生成的两个风险与验证办法

Prefill 的 ConvState 写回

风险　Decode 会把写回的卷积状态当作历史输入。即使首个 token 相同，下一步也可能从不同的状态开始计算。

如何定位　在四层图中先取第一层（L0）更新算子的 QKV、旧状态和更新控制量，对照当前卷积输入 padded 与新状态 new_conv_state。用同一份输入计算参考窗口和写回值，再核对 Decode 实际读回的状态，区分输入偏差、更新偏差和读回偏差。

Decode 的全注意力层

风险　该层已观察到偏差。过去的 K/V 缓存和本步注意力计算都会影响输出，具体出错位置及对后续选词的影响待实测。

如何定位　固定同一 token、层输入、位置、掩码和参考 K/V，比较 Q/K/V、RoPE、注意力输出和新增缓存，再换入 Prefill 实际生成的 K/V 重跑，区分缓存带入的偏差与本层新增的偏差。

连续生成的验收条件　确认写回值与参考状态对齐、下一步读回同一份值，并用同输入单步对照验证全注意力层的输出和新增 K/V。随后在多条提示词、不同有效长度下连续生成，记录逐步 top-1、前两名分差和首次分歧位置，检验当前首 token 的结果能否推广。

本轮已解决的问题

问题位置已完成的修改解决了什么
输入 embedding与 310P 按相同的 embedding 输入路径做对照。消除了入口取数方式不同对逐层比较的干扰。
量化矩阵乘修正 QuantBatchMatmul 的 scale 类型，W4 分组权重 scale 使用 FP16。量化投影按约定的数据类型使用权重缩放因子。
SiLU、Softplus、RMSNorm针对这三项已知精度问题编写自定义算子。为激活和归一化提供了可独立验证的精度实现。
RoPE 位置编码Q/K 的旋转升至 FP32 计算，再转回后续需要的类型。减少了旋转计算过程中引入的舍入误差。
GDR 有效长度修正 effective_length，传入真实的有效 token 数。递推更新按有效序列长度执行，避免把补齐位置计入更新。
MoE 共享专家门控使用 FP16 的 linear 结果直接进入 sigmoid。共享专家的门控权重按修正后的精度路径计算。
OMC 模型加载减少图中多余的 cast，修复本次配置的加载失败。目标模型能够加载并执行，板端可继续产出用于精度对比的结果。
