# Draft优化策略与实测收益

更新：2026-11-06。当前保留完整六层、全词表、C16／cap192／K15的 **packed Draft约60ms基线**。离线权重转置及NZ／ZN探索暂存档，下一阶段处理Target精度。设备数据来自用户回传；完整Draft的原数值门槛仍未通过，性能基线不代表精度或生产验收通过。

## 已采用的改动

下表的“省时”是指定前后两轮的观测差额。**不同计时范围不能相加**，组合改动没有单项消融时不拆分功劳。完整数据见[结果页](results.md)和[执行状态](../specs/dflash-execution-state.json)。

| 改动 | 做了什么 | 前→后 ms | 观测省时 | 测量范围与限制 |
|---|---|---:|---:|---|
| 空间投影＋投影合并＋GQA reshape＋共享RoPE | 16行特征放入4×4空间块；合并K/V与gate/up；避免复制KV heads；共用位置计算 | 627.647 → 245.989 | 381.658ms，60.8% | 两次完整模型vendor inference；单次profile、组合改动，不能给每个子项单独分配收益 |
| 同一轮Conv热点变化 | feature Conv从batch方向改为空间patch，保留完整K=16384点积 | 69.038 → 8.664 | 60.374ms，87.4% | 算子duration；属于上一行内部观察，不能再加到整图收益 |
| 四维入口重排＋共享mask | 两个rank4 Transpose；滑窗／全注意力mask各构造一次 | 287.7584 → 193.7716 | 93.9868ms，32.7% | 各38次混合诊断调用的加权同步API均值；不是配对稳态测试 |
| 控制图整理＋RoPE phase表＋host embedding | 有效位先以INT32处理；预计算位置×频率；CPU查FP16 embedding，让NPU主体合并 | 193.7716 → 104.8019 | 88.9697ms，45.9% | 两轮38次加权API均值；中间各步无独立时延，host查表／准备时间未计入，不能全部归因于embedding |
| NPU StableArgMax替代CPU全词表ArgMax | 保留全部248320 logits，有限FP16、并列取最小索引，输出60字节INT32 | 104.802 → 66.554 | 38.248ms，36.5% | 两轮38次加权API均值；非配对稳态，不能将全部差额当作归约内核本身省时 |
| CPU feature pack | 把512KiB入口的两次设备Transpose改为预分配CPU缓冲中的FP16字置换 | 66.4573 → 60.7651 | **5.6922ms，8.565%** | 完整模型38次原调度对照，包含CPU pack、SetInput／ReuseInput及API；488个有效输出区域逐字节一致 |

空间布局组合之后的245.989ms是单次vendor inference；下一行的287.7584ms是混合输入API均值，二者不矛盾，也不拼成一条同口径时间曲线。早期GE常驻闭环的608.155ms使用不同模型和调度，不用它计算当前60ms版本的端到端加速比。

CPU feature pack另有投影前缀实验：3组输入，每模型预热3次、记录10次，30对输出逐字节一致；三组平均净省5.1496ms，包含CPU准备。完整模型的5.6922ms才是采用这项改动的整图依据。两份模型仍分别加载，文件I/O、快照、KV诊断回读、commit与加载不在计时内。

## 同样保留、尚无独立省时数字的改动

| 改动 | 当前作用 | 时延结论 |
|---|---|---|
| 增量committed KV | 六层只把新增context写入12路ND缓存；候选KV临时使用 | 与旧全前缀重算未建立同条件配对，暂不报单项收益 |
| 内置RmsNorm和组合attention | 当前PyTorch图使用RmsNorm与QK／Softmax／PV；弃用不满足本合同的融合attention路径 | 是当前图的组成部分；未隔离测得RMS或attention替换收益 |
| 预计算FP32 RoPE Sin/Cos | 避免已观察到的phase先降FP16导致的系数误差；覆盖全部合法表位置 | 精度修复；修复后API仍约66ms，没有单独加速结论 |
| 源权重Transpose折叠 | 普通ND权重保持[N,K]，编译准备删除Transpose节点并设置transpose_x2=true | 已在当前基线；没有证据证明内部完全免搬运，也没有独立收益 |
| 常量物化、Reshape简化、单位scale消除 | 减少静态控制和view节点，保持公开接口 | 无独立消融，不填估算数字 |
| host embedding移出OMC | 完整embedding仍供CPU查表，OMC约2.808GB降到1.791GB | 文件减少约1.017GB；不是等量运行时省时证明 |

## 未采用或已停止的实验

| 实验 | 结果 | 决定 |
|---|---|---|
| 4×4 feature Conv改2×2 | 前缀准备＋API 10.7675 → 10.9381ms，平均增加0.1706ms；30对输出均非逐字节等价，范围重叠 | 无净收益，未进入整图 |
| 31个静态权重离线W.T，ND／transpose_x2=false | 最新整图38次加权准备＋API **60.4067 → 73.6574ms**，增加13.2507ms（21.94%）；488个区域中487个相等 | 暂停；保留原ND／transpose_x2=true基线 |
| NZ逻辑／存储分离导入 | 18个NZ用例中17个有区分度的用例全失败；全部180份输出匹配“分块字节按普通ND读取”的预测 | 拒绝本次导入合同；不声称硬件不支持NZ |
| FRACTAL_ZN字面格式导入 | 所选DDK导入层报不支持该格式，未执行设备计算 | 暂停；不否定mmad内部L0B的ZN格式 |
| HIAI V1改V2 | 单次inference 245.989 → 258.682ms，未见收益 | 保留V1，不能推断V2在所有场景都更慢 |
| 零追加KV专用图 | 正常调度通常合并新增context与proposal；未部署原型 | 无设备收益数据，暂缓 |
| 内置Top1拆分、TopK／比较树 | 未得到满足完整词表合同的纯NPU替代 | 当前采用独立验证过的StableArgMax |

离线W.T唯一差异在isolated第0例的draft_hidden：608个元素不同，最大差3.494140625。基线该例所在hidden L2上限13.727%，候选上限1.498%；不能把这一个差异直接说成转置导致新的精度恶化。两边Top1差异与KV失败计数相同，仍没有整体精度通过。候选没有速度收益，本阶段不继续排查它。
