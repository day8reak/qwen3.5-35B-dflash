## Draft单次算子Profiling

用户回传`draft-s64-profile-v2`的CSV，模型工具PID45599，模型与厂商转换工具退出码均为0。以下为原表记录；输入为保留的S64特征，与上面的18-token文字请求不是同一次执行。

| 算子 | CSV执行设备 | 本次记录耗时 |
|---|---|---:|
| `__ge/v20/full_dot_conv/output(Convolution)` | npu_aicore | 282.430 ms |
| `__ge/draft_logits/flat_output(MatMul)` | npu_aicore | 19.912 ms |
| `draft_top1(ArgMaxExt2)` | cpu | 13.058 ms |

对照当前导出源码，`v20`是入口`draft.fc`，将`[1,64,16384]`投影成`[1,64,2048]`。它采用4×4 Conv2D表达完整点积，源于此前选定编译器拒绝该MatMul的`K=16384`。这是当前首要排查项；不能直接切回已被拒绝的普通MatMul。

新C16增量图只投影16行，但仍沿用此Conv2D路径；缓存命中后应避免重复处理历史行，静态C16仍会计算其固定16行。`max-draft-tokens`控制候选宽度，不改变投影的16384输入维度。优化顺序为入口投影与增量KV、全词表head／Top1，再评估CPU小算子的调度开销。保留原权重和数值边界，新实现须先做Draft独立数值比较。

此表尚不能解释整次SDK时延，也不证明50ms可达。CPU与NPU记录的开始时间不能直接拼成执行时间线；不把各行求和或与另一请求的726.839ms相除来推断占比。小算子本体耗时较低也不能排除设备间调度成本。
