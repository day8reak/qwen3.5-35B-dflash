# Lessons

适用范围：本项目用户提供的X90 CPro DDK/allops；未推广为其他芯片或版本规则。

- **包装生成与源码复制分开核验。** allops从ascend310b INI生成PY，旧host只有kirinx90配置而被遗漏；cpp仍可由glob复制。补注册后用户确认INI、包装和OMG均通过。build.sh存在退出码变量混用，末尾成功文字不作唯一证据。
- **区分注册、路径和实际导入。** 日志打印实现文件路径不证明文件存在；先查文件再查包解析。内部impl路径与缺失PY是两件事，均已修复；不手写厂商包装替代生成流程。
- **复用已确认的环境修复。** GE入口需透传既有TBE诊断及progress回调。复用有效AIR，不为收集日志重新编译；平台参数仍kirinx90。
- **保持服务器分工。** allops及GE/OMG不依赖TorchAir；权重服务器承担Torch schema/Meta/converter。用户只需复制三个自有源码，无需回传归档。
- **证据逐层闭合。** 主机、编译、图层面落点、设备数值和性能分别记录。Qwen配置现已七组、70次设备精确且稳定；其他shape、310P和整模型不继承通过状态。
- **命令只保留当前推荐路径。** 当前阶段页写启动/回收，结果页写测量与限制；旧排障保留Git历史，不随每次修复继续堆进操作页。

本轮复用了lean-model-development已有文档规则，未新增重复技能或上传新测试。已观察到Qwen输入组的并列/subnormal、大索引及尾写正确，API均值约1.232ms。17行分批输出后的复用、8193列非对齐行起点仍需单独验证；本次观察不推广为通用平台规则。
